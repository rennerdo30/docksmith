---
title: Architecture
description: How the Swift CLI performs a selected, read-only probe.
---

The Swift package has two products: the `DocksmithCore` library and the `docksmith` executable. The CLI handles arguments and presents a compact report; the core resolves and runs Apple's separately installed `cfgutil`, parses its responses, and models check states.

The flow is deliberate: `devices` discovers connected devices, and `probe` requires a selected device. A probe discovers again, checks the selection, requests `installedApps`, then requests the icon layout. It derives counts and warnings without returning raw inventory or layout contents in the public report.

Responses can be incomplete. A decodable response accompanied by a nonzero `cfgutil` status retains its decoded count and adds a partial-result warning. Malformed or missing data is reported as indeterminate. The current code does not issue device-changing commands.

Run `swift test` from the repository root for parser and device-selection checks. When filing issues, share commands and redacted warnings, never device identifiers, pairing material, app inventory, or raw device reports.
